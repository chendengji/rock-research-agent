# S3 理解 → knowledge.v1.json

**目标**：读懂这篇论文，产出一个带证据的知识结构。**理解是 LLM 的认知工作，不是填表**——论文各不相同，没有万能骨架；本文件只提供两样东西：**思维提示词**（帮你理解得更深）和**刚性证据规则**（L0，脚本事后校验）。结构、层级、详略、重点全部自主。

## 0. 分工（先想清楚边界）

| 层 | 谁说了算 | 内容 |
|---|---|---|
| **证据规则（L0 刚性）** | 脚本校验 | `fact` 必须带 page + 逐字 quote；reliability 必标；不编造；quote 不改写 |
| **工作方式（建议）** | LLM 可换 | 三遍读法、分节喂给模型——这是注意力管理技巧，不是流程义务 |
| **内容（完全自主）** | LLM | 章节骨架、层级、节点取舍、叙事线、详略、重点排序——按论文自身的逻辑组织 |

为什么分节喂模型不是模具：一次喂全文会导致后半段质量骤降（长上下文注意力衰减）。分节是执行机制，与内容无关。

## 1. 内容画像（读完先给用户一句话，不阻塞）

读摘要 + 引言 + 结论后，给 3-5 个**描述性标签**（如"试验主导 / 含数值验证 / 提出新判据 / 方法对比"）+ 一句话告知用户，然后**直接继续**（用户可随时打断纠正）。画像的唯一作用：帮你判断哪些节值得深读、后续选图作弱先验。

## 2. 三遍读法（方法而非义务）

1. **定位**：摘要 + 引言（末段常是真 gap 所在）+ 结论 + 全部图/表 caption。回答三个问题：这篇论文在回答什么问题？**它真正新的贡献是什么**（区别于背景铺垫）？新鲜内容集中在哪几节？（caption 常浓缩了最硬的结果，别跳过。）
2. **深读**：按第 1 遍的定位逐节精读，自由归纳节点（提示词见 §3）。
3. **核对**：回原文比对 quote/页码；匹配不上的标 `unverified`，不许改成"大意"。

## 3. 深读提示词（本阶段的核心资产，整段使用）

### A 定位骨架（第 1 遍）

```
你在预读一篇论文。只输出 JSON。

输入：abstract / introduction（尤其末段）/ conclusion / 全部图表 caption

回答四个问题，每个都用论文里的事实支撑：
1. 问题：这篇论文试图回答或解决什么？
2. gap：引言指出的真实缺口是什么？（留意 "rarely reported / not yet / limited" 这类句子，
   引言埋的缺口通常比参数局限更接近作者本意；分不清主次就两个都记，后续再收敛）
3. 主张：作者最核心的 1-3 个主张是什么？（用自己的判断句，不是章节名）
4. 结构：按论文自身的逻辑给出它实际的组织方式（不是"按模板应该怎么分"），
   标出各节的角色（gap/body/result/limitation/method 等）和值得深读的优先级。

纪律：只从看得见的文本里找，不确定就留空；宁少勿编。
输出：{"problem":"","gap":[""],"claims":[""],"outline":[{"title":"","pages":[a,b],"role":"","priority":"high|normal"}],"top_nodes":["主张的种子节点，每个是≤40字判断句，含页码"]}
```

### B 深读抽取（第 2 遍，逐节）

```
你在精读一篇论文的一节，为知识结构抽取命题。只输出 JSON。

## 理解目标（不受格式的部分，先想后写）
- 你要做的是"把这一节的知识带到半年后"。先自问：
  · 如果只能带走这一节的 3 句话，是哪 3 句？
  · 这节里什么是**作者真正新鲜**的内容，什么是领域惯常的铺垫？（铺垫要压缩，新鲜要展开）
  · 效果背后的**机制/为什么**是什么？（作者给了解释吗？给了就保留，没给就诚实留白或标 prior）
  · 每个主张的**成立条件**是什么？（含水率/加载速率/围压/岩性/尺度……没写条件的结论是弱结论，别把它当硬结论）
- 层级和分支完全按这一节内容自身的逻辑组织：拆分点选在知识真正的分界上（方法之间、
  工况之间、机理层次之间），不套任何预设框架。该有多平就有多平，该有多深就有多深。
- 区分三种话：作者的话（fact）、你由作者前提推的（inference）、你基于常识补的（prior）。
  这是知识的证据强度，宁可少标 fact，不可把归纳语气混进事实。

## 表达规范（刚性，每节点必守）
1) text：≤40 字的**判断句**，可独立阅读。要带信息量：数值（430→93）、条件（含水率 100%）、
   机理（卸压降应力）、或明确的否定/批判（B1 不能单独用）。名词短语和标题是目录，不是知识。
2) 数值必带单位与条件，如 "32%（饱水 72 h，单轴）"。
3) quote：逐字复制本节原文，≤400 字符；不改写、不翻译、不拼接不连续句子（跨段用 " … "）。
4) reliability 必标：fact / inference / prior（inference 与 prior 要在 detail 里写依据）。
5) kind 只是角色标签，按实际内容选（question/gap/method/evidence/claim/mechanism/limitation/term），不要硬凑枚举。

## 经验教训（实践中反复出现的失败模式，勿重蹈）
- "水对岩石有弱化作用"——正确但零信息。这类话不发节点，量化或具体化后再来。
- 把方法写成步骤清单——编号步骤属于流程（记在 detail 或留给 flow 层），节点要下判断：
  "方法 A 在精度上优于 B，代价是 3 倍耗时"。
- 把"我总结的"标成 fact——你归纳的一律 inference 或 prior。
- 为显得完整而罗列参数、凑同义节点——一个信息一节点，重复与空话直接丢弃。
- 一节抓太多导致琐碎——优先级：核心结论/结果 > 机理与条件 > 方法要点 > 术语。超出就是过度捕获。

输出：{"nodes":[{"id":"","text":"","detail":"","page":0,"quote":"","reliability":"","kind":"","parent_hint":""}],"edges":[{"from":"","to":"","rel":"supports|contradicts|refines|requires|part_of|contrasts"}],"glossary":[],"directions_found":["这一节里主动挖到的方向，如：引言真缺口/双验证/机理总结/关键数值"]}
```

### C 方向性清单（L1 弱引导，不是模板）

不同性质的论文常有各自"值得找的方向"。**提取时发现一个方向就自问一句"找到了吗"；原文没有就不硬凑，混合类混着用，也允许清单之外的视角。**

- **综述/方法对比**：作者亲笔总结句（现成观点句，fact 优先于你归纳）；各分支的由来 → 应用场景 → 优缺点三要素（原文没有的要素不硬凑）；方法间的对比维度（原理/精度/效率/适用条件）；领域目前的矛盾与共识。

  **研究现状的写法——只做总结式，罗列式仅辅助（关键区分）**：
  · **总结式（主要产出）**：把已有工作进行**特征总结**——按方法/原理/精度/效率/适用条件等维度归类，形成「某类工作共同特征/规律/差异」的判断句。这才是有理有据的知识，也是 S4 算法关系/对比图的**节点与边**来源。
  · **罗列式（仅辅助）**：「某某做了……」的流水账**不是知识**，只作总结式的支撑证据，且**只保留开创性 / 首次 / 重要 / 出名 / 行业知名**的工作（如首个提出某方法、领域奠基者、被广泛引用的代表作）；**普通工作不列举**（流水账意义不大，且撑不起节点）。
  · **区分三类**：① 方法（怎么做：算法/流程/判据）② 理论（为什么：机理/模型/条件）③ 论文罗列（谁做了什么：仅辅助）。节点 `text` 用①或②的判断句；③只进 `quote`/依据，**不单独成「某某做了……」节点**。
  · **绘图衔接**：总结式的特征归类 + 方法间关系（`refines/contrasts/part_of`）→ 供 S4 算法关系/对比图投影；罗列的人名仅作辅助标注（如「董陇军[81]（首个无需测速）」）。
- **试验**：试验目的与工程背景；材料/工况/加载路径的条件网格（哪些组合试过、哪些没试）；流程链（供 flow 投影）；关键数值进 text；条件的限定语别丢。
- **数值模拟**：模型/本构/标定三件套；**验证常有两层——材料参数校准验证 + 模型验证（网格/两步/边界）**，自查是否两个都找了；关键定量结果（单元数/最优参数/破碎区尺寸/能量值）进 text；结论里的**机理总结**（不只"可行/有效"，还要"为什么有效"）。
- **理论**：假设清单（假设即边界）；推导链的关键跳步；适用条件；与既有理论的对比与验证证据。
- **工程案例**：现场概况与工况；监测手段与数据量级；现象→机理的分析闭环；对设计的回写。

### 领域口径（子功能，可选但推荐）

涉及岩爆/断裂/隧道/脆性/SHPB/AE 等，先注入领域字典，节点命名不自造名词：

```bash
$PY scripts/domain.py --prompt                      # 全量口径
$PY scripts/domain.py --prompt --area-filter rockburst,dynamic-fracture  # 按主题
```

把输出作为"领域口径"块加入 A/B 提示词。规则：节点 `text`/`glossary` 用字典标准术语；判据/公式直接引用（如 `σ_θ/σ_c`、`W_et`、Hoek-Brown 2002）；论文自己的参数名保留，挂到 `glossary`。详见 `core/domain.md` §3。

## 4. 合并与校准（可脚本化）

- 去重：`text` 归一化后相似度 > 0.85 视为同节点，保留 quote 更完整者；合并保留 `merged_from`。
- 挂树：`parent` 由内容逻辑决定（A 骨架的优先级 + B 的 parent_hint 供参考，最终以知识分界为准）；无合适父节点挂 `outline` 对应节。
- 重编号：按 outline 顺序 + 出现页排序，`N01…`。
- importance：由你按理解给分。标准只有一个——**"如果只保留这篇论文 10% 的内容到半年后，会保留哪些"**：会保留的接近 0.9，备查的 0.5，背景铺垫 0.2。参考信号（摘要/结论出现、有量化结果、被多处呼应、是方法链一环、作者自述局限 vs 纯背景）只辅助校准；**必须拉开差距**，全在 0.8 上下等于没有评分。

## 5. 产出与自检

`knowledge.v1.json`（契约见 `core/contracts.md`，含 thesis/narrative/insights/open_questions，见 SKILL.md §2）+ `logs/llm/*.json`。

```bash
$PY scripts/validate.py --paper-dir . --level kmap
$PY scripts/validate.py --paper-dir . --level evidence
```

自检清单（证据层刚性 + 理解层自查，不查认知层节点数量）：
- [ ] 引文回溯率 ≥ 95%；每个 fact 节点 quote 在对应页能找到
- [ ] `kind=claim` 的节点能在正文找到对应句，不是"我总结的"
- [ ] thesis / narrative / insights 已写、标了 reliability、inference 带 basis
- [ ] A 骨架的 gap 与主张在深读中都有节点回应（回应不上就要么降级要么说明）
- [ ] 深读时 `directions_found` 清单回看一眼：提示过的方向都落节点了吗？没落的是"原文没有"还是"漏挖"？是后者就回读那一节

节点数量**不设上限也不设下限**——质量说话。渲染预算（≤60 节点等）由 S4 处理（聚合/分视图），不要在理解阶段删内容。

## 6. 常见坑速查（= §3 经验教训的压缩版，交付前扫一眼，命中一条改一条）

走步骤清单没判断 → 改成判断句。正确但零信息 → 量化或删。归纳冒充 fact → 改标 reliability。同义凑数 → 合并。关键数值躺在 detail 里没进 text → 提上来。结论只说"有效"没说机理 → 补机制或标注。无条件的绝对结论 → 补成立条件或降级。
