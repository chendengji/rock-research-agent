# 核心原则：为什么必须是"知识模型 + 投影"

## 0.5 技能只提供选择项

内容画像标签（描述性标签，不硬分类）、各类"值得找的方向"清单（L1 弱引导，可混合可增删）、图映射、可靠性档位——都是**给 agent 的选择项**，由 agent 依据内容+用户偏好**自主决策**，不硬性限制。方向清单是"提醒去找什么"（原文没有就不硬凑），图映射是建议主图（可换）。技能不写死任何一条路径；**分解结构由论文自身逻辑决定，不由模板决定**。

## 0.6 约束少而精，引导足而柔（设计权衡）

**约束（硬性）只留红线**：禁止无出处断言、禁止编造、reliability 必须标、必须有 page/quote 来源。这是"不犯错"的下限，极少且不可协商。

**引导（柔性）要足**：画像标签/方向清单/图映射/可靠性档位/验证提示（如"数值模拟可能有材料参数验证+模型验证两个验证"）都是**方向提示**（"这里有，去找找看"），不是"必须写 X 条"。agent 依据内容+偏好取舍。

**内容层完全 LLM 自主**：具体节点怎么总结、措辞、判断哪个结论重要、挖掘多深——技能不写死，agent 充分发挥。

**三层设计**：红线层（约束，极少）→ 结构层（引导选择项，不写死）→ 内容层（LLM 自主）。遗漏的根因是**引导不足**（该提示的方向没提示），不是约束不足——所以补**检查清单**（提取自查：有没有提研究缺口/机理总结/数值模拟验证是不是两个/关键数值在不在 text），而非加硬约束。硬约束会逼 agent 硬凑、僵化；检查清单让 agent 自己挖到。

## 0. 三遍读法（Keshav 2007，检索经验）

读论文分三遍，别一遍到底：
1. **第一遍（骨架）**：标题/摘要/引言末段/结论/图——定位问题、缺口、核心主张和"新鲜内容在哪几节"（提示词见 `stages/s3-kmap.md` §3A），~5 分钟；
2. **第二遍（深读）**：按论文自身逻辑逐节精读，自由归纳节点（fact/inference/prior 标记），是主工作；
3. **第三遍（验证）**：回原文核对 quote/页码，标 unverified；批注回流时补权重。

## 1. 图不是产物，是视图

直接让模型写 Mermaid 的后果：改一个节点要重写整张图，批注回流时无法局部更新，两个视图（脑图/流程图）会互相矛盾。

所以：**模型只编辑 `knowledge.json`，渲染是确定性脚本**。这样：

- 同一份数据能出 4 种图（tree/mindmap/hierarchy/flow），口径必然一致；
- v1→v2 可以 diff，用户能看见"agent 改了什么"；
- 图崩了重渲染即可，不用重读论文。

## 2. 选图：拓扑特征为主，内容画像作弱先验

| 图 | 角色 | 结构 | 上限 |
|---|---|---|---|
| **思维导图 tree** | **主产出**：把文字内容结构化（主题→分支→特点），一目了然 | 标题→章节→节点→子节点 | ≤60 节点、≤4 层 |
| **脑图 mindmap** | 辅助：看概念/节点间关联 | 放射状 | 6 分支 × 6 子节点 |
| **层次图 hierarchy** | 辅助：论证链 | 问题→Gap→方法→证据→结论→局限 | 4 层 |
| **流程图 flow** | 辅助：试验方法/做法 | 输入→处理→观测→输出 | 9 步 |

**怎么选（先看拓扑，画像只作修正）**：
```
先看 knowledge.json 的拓扑特征：
  分支多且平级（主题→各方法→特点）   → tree
  时间/阶段序强（年份→进展）          → timeline
  因果/流程链明显（取样→加载→观测）   → flow
  层级分类清晰（论证链/分类体系）      → hierarchy
再看 content_profile 作弱先验修正（如"综述 + 方法演进史"偏向 timeline）。
```
不再"综述→tree、试验→flow"一对一映射——同一篇综述可能既有 tree 又有 timeline，同一篇试验论文结果分支多时主图也可能是 tree。主图 1 张；辅助图按需，不默认全出。

不要用脑图表达流程，也不要用流程图表达论证。混用是"看起来丰富、读起来没信息"的主因。

## 2.5 可靠性三档（证据强度，与 kind 正交）

每个节点标 `reliability`，是"这句话可不可信"的证据强度，不是命题角色：
- `fact`：原文直接陈述（数值、结论、参数）——最强；
- `inference`：由事实推理（机制、归因、分析）——中；
- `prior`：基于知识（LLM 归纳、背景知识、文献常识，无直接原文）——弱，需标"LLM 归纳"。

作者总结句（综述类）优先 `fact`；LLM 自己归纳的一律 `prior`，不能当原文证据。

## 3. 证据链只有一种写法

节点 = 一个**可验证命题**，不是一个章节标题。

- ✅ `饱水 72 h 后砂岩单轴抗压强度下降 32%（p<0.05）`
- ❌ `结果与讨论`（这是目录，不是知识）
- ❌ `水对岩石有弱化作用`（无量化、无出处）

`quote` 必须逐字复制原文（允许省略号连接两段），`page` 用 PDF 0 基页码。校验脚本会做归一化子串匹配；匹配不上就标 `unverified`，不许悄悄改成"大意"。

## 4. 批注是监督信号，不是摘要素材

用户的一条批注至少携带 4 种信息：

| 信号 | 来源 | 用途 |
|---|---|---|
| 位置 | `annotationPosition.rects` | 精确对齐到文本块 → 节点 |
| 颜色 | `annotationColor` | 语义（关键/反驳/方法/图）→ 权重 |
| 原文 | `annotationText` | 与节点 `quote` 比对，确认是同一句 |
| 批注文字 | `annotationComment` | 用户的判断，优先级高于 agent 的解读 |

多数批注没有文字（实测库里 224 条只有 26 条有 comment），所以**不能依赖 comment 做语义**，必须靠位置 + 原文对齐。

## 5. 重聚焦要做两件事，不只是删

- **压**：没被批注、也不支撑被批注节点的分支 → 折叠成父节点的一条 bullet 或删除。
- **提**：被批注但 v1 里没有的内容（用户常标"原文没强调但对我有用"的细节）→ 新建节点，`kind=user_note`，`importance` 从颜色权重起算。

只做"删"会让图越来越空，最后只剩用户已经知道的东西。

## 6. 不做什么

- 不写文献综述、不做多篇对比（那是 `research-core` / `research_analyze` 的活）。
- 不翻译全文（`nature-reader` 的活）。
- 不修改 PDF、不写 Zotero（除非用户明确要求写回笔记）。
- 不为"看起来完整"补造节点。宁可 30 个真节点，不要 60 个半真半假。
