# 成稿：批注驱动的 PPT

## 0. 场景→叙事框架（先定场景，再定页数）

借鉴社区成熟产品（dsh-paper-slides / academic-slides / PPTAgent）的"场景驱动"模式：先定**给谁讲、讲多久**，再定叙事框架，不要一上来就排页。

| 场景 | 时长 | 页数 | 叙事框架（社区共识） | 重点（页型） |
|---|---|---|---|---|
| 组会文献分享 | 15 min | 8–12 | **跳过背景，花在"做了什么 + 卡在哪"** | 方法 + 关键结果 + 我的判断 |
| 会议/综述引用 | 12 min | 5–7 | **一个 message**，每页都服务它 | 只讲与课题相关 2–3 点 |
| 答辩/开题 | 25 min | 12–20 | **贡献是否是你的 + 是否知道局限** | 贡献 + 局限 + 下一步 |
| 自己复习 | — | 6–8 | 脑图 + 批注原话 | 少解读，能召回 |
| 给导师汇报进展 | 10 min | 6–10 | "这篇能怎么用到我的实验" | 可复用点 |

框架决定 `deck.json` 的页型顺序；不确定就问用户（见 `stages/s7-deck.md` §1）。

## 1. 叙事骨架（10 页，按需增删）

| # | 页型 | 内容 | 图 |
|---|---|---|---|
| 1 | cover | 标题 + 一句话结论 + 场景 | — |
| 2 | claim | 为什么读它：与我研究的关系 | — |
| 3 | outline | 全文骨架（结构树 v2，主产出） | `tree.svg` |
| 4 | figure | 方法流程（只标被批注的模块） | `flow.svg` |
| 5 | figure | 关键结果图（用户框选的 image 批注优先） | `ann/xxx.png` 或 `figs/Fn.png` |
| 6–8 | annotation | 逐条批注：原文截图 + 我的批注 + 我的解读 | `ann/xxx.png` |
| 9 | map | 我的理解路径（脑图局部，不是全图） | `mindmap.svg` |
| 10 | limits | 局限 / 可复用点 / 下一步 | — |

原则：**一页一个信息点**。宁可 10 页讲透，不要 20 页念稿。

## 2. 批注页版式（最重要）

16:9（13.333 × 7.5 in），左右分栏：

```
┌──────────────────────────────────────────────┐
│ 标题：B1 不能单独用                     28pt │
├────────────────────────┬─────────────────────┤
│ 原文截图（左 45%）      │ 我的批注（右 50%）  │
│ 红框标注命中区域        │ · 用户 comment      │
│ 图注：p.223, Red       │ · agent 解读（≤3行）│
│                        │ · 与哪条结论相关     │
├────────────────────────┴─────────────────────┤
│ 页脚：item_key · 论文短标题 · 页码            │
└──────────────────────────────────────────────┘
```

- 截图**保留上下文**：在批注 rect 外扩 12–20 pt，否则孤立一行字看不懂。
- 截图里用半透明红框标出批注范围（`build_deck.py --mark-rect`）。
- 用户 `comment` 为空时，不要编造"用户想法"；改写为"原文强调"并注明"（无文字批注）"。

## 3. SVG 进 PPT

目标：**图在 PPT 里是可编辑形状，不是图片**。但实测有两个 PowerPoint 的坑，必须按图型分流：

| 图型 | 进 PPT 方式 | 原因 |
|---|---|---|
| 层次图 / 流程图 | 路线 A：COM 插 SVG（可编辑） | PowerPoint 能正确渲染 flowchart 型 SVG |
| 脑图 mindmap | **路线 B：插 PNG**（2x 高清，不可编辑） | PowerPoint 的 SVG 引擎会把 mindmap 里"深底白字"节点渲染成**空白框**（实测，`--svg-backend com` 下 `mindmap.svg` 约 1/3 节点文字消失） |
| 批注截图 / 图注裁剪 | 路线 B：PNG | 本来就是位图 |

`build_deck.py` 图片**一律用 PNG**（svg 自动取同名 `.png`，无降级、不写 svgplan）——`render_maps.py` 已产出 2x PNG，直接插入，无 PowerPoint SVG 渲染坑（mindmap 深底白字/丢字问题不存在）。可编辑的 `.svg` 始终留在 `maps/`，返工改图不受影响。

> 路线 A（COM 插 SVG，可编辑）不再默认：改为 PNG 默认（稳、无降级）；要可编辑仍可手动在 PowerPoint 里替换。

路线 A（首选，PowerPoint 2016+）：COM 插入 SVG。

```python
import win32com.client as win32
app = win32.DispatchEx("PowerPoint.Application")
pres = app.Presentations.Open(pptx, WithWindow=False)
shape = pres.Slides[idx].Shapes.AddPicture(svg, False, True, left, top, width, height)
pres.Save(); pres.Close(); app.Quit()
```

插入后右键"转换为形状"即可拆成可编辑节点。**注意**：PowerPoint 的 SVG 文本排布用自家字体度量，比 Chrome 略宽，flowchart 节点文字偶尔会比 mermaid 画的框多折一行而轻微出框——可接受，但**不要把节点文字排到框的极限**（见 `kmap2mmd.py` 的 `per_line` 参数，已为 PPT 预留余量）。

路线 B（降级）：python-pptx 插同目录同名 PNG。可看不可编辑，必须在交付时说明（脑图默认就是这条）。

路线 C（要"打开即形状"）：SVG → EMF（Inkscape/LibreOffice）再插入。本机未装这两者，不作为默认；装了以后 EMF 取消组合是形状，但字体与箭头会走样。

`deck/svgplan.json` 记录每张 SVG 的目标页、坐标与 `degraded_to_png` 标记，返工时不用重排整份 PPT。

## 4. 排版硬约束

- 字体：`Microsoft YaHei`（正文）/ `Microsoft YaHei` 加粗（标题）；不要混用宋体。
- 字号：标题 28–32，正文 16–18，图注 11–12，**全局不小于 12**。
- 行宽：中文 ≤ 32 字/行，英文 ≤ 60 字符/行。
- 项目符号：每页 ≤ 5 条，每条 ≤ 22 字；第 6 条一定溢出。
- 图占页面 40–60%，四周留白 ≥ 0.5 in。
- 页脚统一：`citekey · 短标题 · p.X`。

## 5. 备注（speaker notes）

每页都要有，写"讲什么"而不是"这页是什么"：

- ❌ "这一页介绍方法流程图。"
- ✅ "先指左边输入，强调他们只做了单轴，然后停在 AE 那一步——这是我们能接的地方。"

开头 30 秒和结尾 60 秒单独写完整句子，其余可用要点。

**出处进备注，不上正文**：观众读页面、讲者读备注。图源文件、批注 key 由 `build_deck.py` 自动追加到备注末尾（`[来源] 图源：… · 批注：…`），正文只留结论——脚本已内置，不用手写；页脚的 `citekey · 短标题 · p.X` 保留。

## 6. 交付前

1. 用 PowerPoint 打开，翻一遍：有没有文字压图、图有没有糊、SVG 有没有空白。
2. 导出 PDF 存 `deck/deck.pdf`（汇报备份）。
3. 生成图源清单：每张图 → 文件 + 页码 + 来源（自绘/原文/批注截图）。
4. 一句话告诉用户：页数、批注覆盖了几条、哪几页是"我的话"而不是"作者的话"。
